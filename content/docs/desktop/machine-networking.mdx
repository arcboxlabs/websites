## Default Setup

Each machine gets a virtual interface on the ArcBox network and an address from ArcBox's DHCP server. Outbound internet access works immediately; nothing to configure.

## Connectivity

| Direction | How |
|-----------|-----|
| Machine → Internet | Through the host datapath, automatic |
| Mac → Machine | `<name>.arcbox.local` |
| Machine → Mac | `host.docker.internal` |
| Machine → Machine | `<name>.arcbox.local` |

## Port Access

Every port on a machine is reachable from your Mac through its hostname. There is no per-port forwarding to configure:

```bash
# Machine "dev" running several services
curl http://dev.arcbox.local:3000    # web app
psql -h dev.arcbox.local -p 5432     # PostgreSQL
```

This is different from containers, where publishing with `-p` binds a host port. Machines are reached directly at their own address.

## Addresses

A machine keeps its address across reboots. See it on the machine's **Info** tab, or from the CLI:

```bash
abctl machine inspect dev --format json
```

## DNS Inside a Machine

From inside a machine you can resolve:

- Public hostnames, through the upstream resolver
- Other machines and containers, at `<name>.arcbox.local`
- Your Mac, at `host.docker.internal`

## VPN Interaction

The container network lives in `172.16.0.0/12`. If a VPN client claims that range, ArcBox falls back to two more-specific routes rather than fighting for the same one — see [VPN Compatibility](./vpn-compatibility).
