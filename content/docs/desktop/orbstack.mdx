OrbStack set the bar for running Docker on a Mac quickly and with little overhead. ArcBox is an open-source attempt at the same bar — written from scratch in Rust, with the runtime and the app both under MIT OR Apache-2.0.

## Comparison

| | ArcBox | OrbStack |
|--|--------|----------|
| **Pricing** | Free — personal, and commercial during the public beta | Free for personal, paid for commercial |
| **Open source** | Yes — runtime and desktop app | Proprietary |
| **Account required** | No | No |
| **Docker compatibility** | Full | Full |
| **Kubernetes** | k3s cluster managed by the daemon | Built-in cluster |
| **Linux machines** | Built-in | Built-in |
| **Sandboxes** | Built-in microVMs with snapshots | Not available |
| **Zero-config hostnames** | `name.arcbox.local` | `name.orb.local` |
| **GUI framework** | SwiftUI | Native |
| **Intel Mac** | Not yet | Supported |
| **Maturity** | Public beta | Mature |

## What's Better in ArcBox

- **Open source.** Inspect, audit, fork, or contribute to any part of it — the VMM, the VirtIO device model, the networking datapath, the app.
- **Sandboxes.** Disposable microVMs, each with its own kernel, for AI agents, untrusted code, and CI jobs — with checkpoint and restore. The same primitive ArcBox Platform runs in the cloud, so local code scales to a fleet unchanged.
- **A coding-agent path built in.** `abctl claude` drops Claude Code into its own microVM, where the boundary is the hypervisor rather than a permission prompt.
- **A choice of hypervisor backend.** Apple's Virtualization.framework, or ArcBox's own VMM on Hypervisor.framework.

## What OrbStack Has That ArcBox Doesn't

- **Intel Mac support**
- **Maturity** — a longer track record and a much larger user base
- **A polished migration wizard** — ArcBox has `abctl migrate`, which is a CLI command, not a guided flow
- **Machine SSH out of the box** — ArcBox gives you a shell over its own channel; a real SSH server is yours to install
- **Published performance numbers** — ArcBox publishes targets during the beta rather than benchmark charts

<Callout type="info">
  ArcBox is in public beta. If a workflow matters to you and does not work yet, [open an issue](https://github.com/arcboxlabs/arcbox/issues) — that is what shapes the roadmap.
</Callout>

## Migrate from OrbStack

<Steps>
  <Step>
    ### Install ArcBox

    [Install ArcBox Desktop](./install). Keep OrbStack installed until you have verified everything.
  </Step>
  <Step>
    ### Quit OrbStack

    Quit it from the menu bar.
  </Step>
  <Step>
    ### Import Your Workloads

    ```bash
    abctl migrate from orbstack
    ```

    Imports containers, images, and volumes from OrbStack's data directory. Pass `-y` to skip the prompt.
  </Step>
  <Step>
    ### Point the Docker CLI at ArcBox

    ```bash
    abctl docker enable
    docker info
    ```
  </Step>
  <Step>
    ### Recreate Machines

    Machines are not migrated. Create equivalents:

    ```bash
    abctl machine create dev --distro ubuntu --cpus 4 --memory 4096
    ```

    See [Distributions](./distributions) for what is available.
  </Step>
  <Step>
    ### Uninstall OrbStack (Optional)

    ```bash
    rm -rf ~/.orbstack
    ```

    Then remove OrbStack from Applications.
  </Step>
</Steps>

## Hostname Differences

Anything referring to `.orb.local` needs updating to `.arcbox.local`. Compose services get both a `<service>.<project>.arcbox.local` name and their flat container name — see [Domains](./domains).
