## What is ArcBox Desktop?

ArcBox Desktop is a native macOS application for containers, Kubernetes, Linux virtual machines, and agent sandboxes — one three-column window over everything the ArcBox runtime runs.

It ships the `arcbox-daemon` runtime and the `abctl` CLI inside the app bundle and keeps itself up to date over Sparkle, so there is nothing else to install. Everything runs locally, and no account is required.

## How It Works

ArcBox Desktop is a client. It talks to the ArcBox daemon over gRPC for machines, sandboxes, Kubernetes, and system state, and over the Docker Engine API for Docker resources. The daemon owns the virtual machines, networking, and storage.

```mermaid
graph TD
    A["ArcBox Desktop<br/>(SwiftUI)"] -- "gRPC · ~/.arcbox/run/arcbox.sock" --> B["arcbox-daemon<br/>(Rust)"]
    A -- "Docker Engine API · ~/.arcbox/run/docker.sock" --> B
    B -- "vsock" --> C["Linux guest<br/>arcbox-agent"]
    C --> D["Containers · k3s"]
    C --> E["Sandbox microVMs"]
```

Everything is event-driven. The Docker, machine, and sandbox event streams feed the UI, so work started from `docker`, `abctl`, or `kubectl` shows up without a refresh — and vice versa.

## Built from Scratch

Most of the performance-critical runtime is custom rather than vendored: a VMM on Hypervisor.framework with its own device model, VirtIO devices, a userspace macOS networking datapath, VirtioFS sharing, and a vsock guest agent. `linux/amd64` images run on Apple Silicon through [FEX](https://github.com/FEX-Emu/FEX) with nothing to configure.

See [Architecture](./architecture) for the full picture and [Benchmarks](./benchmarks) for performance numbers.
