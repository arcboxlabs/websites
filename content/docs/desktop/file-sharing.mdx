## `/Users` Is Shared at the Same Path

ArcBox shares your Mac's `/Users` into every machine — and into the System VM that runs containers — over VirtioFS, mounted at the **same** path:

```
/Users/<you>  →  /Users/<you>
```

Nothing is rewritten, so macOS paths work verbatim inside the guest. That is what makes bind mounts work without translation:

```bash
docker run -v /Users/you/project:/app my-image
```

Changes are visible in both directions immediately.

## Custom Mounts

Machines can take additional shares at creation time:

```bash
abctl machine create dev --mount /path/on/mac:/path/in/machine
```

Repeat `--mount` for more than one. Each becomes its own VirtioFS share.

<Callout type="info">
  Mounts are fixed at creation. To change them, recreate the machine.
</Callout>

## From the Desktop App

The **Files** tab on a machine browses the guest filesystem directly, with download support — useful for pulling a build artifact out without leaving the app.

## Performance

Shares use VirtioFS, so there is no network filesystem in the path. Sequential throughput is close to native.

Latency-bound workloads are the exception. Something like `git status` over a very large repository does many small metadata operations, and each one crosses the guest boundary. For those, work on a path that lives inside the machine's own disk rather than on the share.
