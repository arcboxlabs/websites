---
title: ArcBox vs Colima
description: How ArcBox compares to Colima, and how to migrate.
---

Colima and ArcBox are both open source, but they are built on opposite premises. Colima is a thin, scriptable layer over Lima, which is itself a layer over QEMU or Virtualization.framework. ArcBox writes the VMM, the device model, and the networking datapath itself.

## Comparison

| | ArcBox | Colima |
|--|--------|--------|
| **License** | MIT OR Apache-2.0 | MIT |
| **GUI** | Native SwiftUI app | None — CLI only |
| **Hypervisor** | Own VMM on Hypervisor.framework, or Virtualization.framework | QEMU or Virtualization.framework, via Lima |
| **Docker compatibility** | Drop-in Engine API | Full, via Lima |
| **Kubernetes** | k3s cluster managed by the daemon | k3s, built in |
| **Linux machines** | Built-in | Via Lima |
| **Sandboxes** | Built-in microVMs with snapshots | Not available |
| **Zero-config hostnames** | `name.arcbox.local` | Not available |
| **Container runtimes** | Docker | Docker, containerd, or Incus |
| **Apple Silicon** | Native | Native |
| **Intel Mac** | Not yet | Supported |
| **Platform** | macOS | Anywhere Lima runs |

## What's Better in ArcBox

- **A native desktop GUI.** Visual container management, streaming logs, an integrated terminal, a merged-layer file browser, and live activity metrics.
- **A purpose-built runtime.** The VMM, VirtIO devices, and networking datapath are written for this workload rather than assembled from general-purpose parts.
- **Sandboxes.** Disposable microVMs with their own kernel, plus checkpoint and restore.
- **Zero-config hostnames.** `name.arcbox.local` for every container and machine.
- **`~/ArcBox` as a real volume.** Container, image, and volume filesystems are browsable in Finder, no copy step.

## What Colima Has That ArcBox Doesn't

- **Intel Mac support**, and Linux hosts
- **Multiple container runtimes** — containerd and Incus alongside Docker
- **A simpler, more debuggable architecture** — it is Lima underneath, and you can drop to `limactl` when you need to
- **Maturity** — a longer track record with fewer sharp edges
- **A pure-CLI footprint** — no GUI to run at all, which some CI and headless setups prefer

## Migrate from Colima

<Steps>
  <Step>
    ### Install ArcBox

    [Install ArcBox Desktop](./install).
  </Step>
  <Step>
    ### Stop Colima

    ```bash
    colima stop
    ```
  </Step>
  <Step>
    ### Point the Docker CLI at ArcBox

    ```bash
    abctl docker enable
    docker info
    ```

    `abctl docker enable` creates the `arcbox` context and makes it the default, replacing Colima's.
  </Step>
  <Step>
    ### Recreate Workloads

    <Callout type="info">
      `abctl migrate` supports Docker Desktop and OrbStack, not Colima. Pull your images and start your containers again — Compose files work without changes.
    </Callout>

    ```bash
    docker compose up -d
    ```
  </Step>
  <Step>
    ### Uninstall Colima (Optional)

    ```bash
    colima delete
    brew uninstall colima
    rm -rf ~/.colima
    ```
  </Step>
</Steps>

## Differences to Expect

- **Kubernetes is not on by default.** Start it with `abctl k8s start`, then `abctl k8s enable` to wire up `kubectl`. See [Kubernetes](./kubernetes).
- **Mounts need no configuration.** ArcBox shares `/Users` at the same path in the guest, so there is no `--mount-type` decision to make.
- **Host ports below 1024 cannot be published.** Port forwarding runs unprivileged. See [Networking](./networking#port-mapping).
