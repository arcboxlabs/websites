## Compose Is Bundled

`docker compose` (v2) ships with ArcBox. `abctl docker setup` installs it alongside `docker` and `buildx`, so there is nothing separate to install and your existing `compose.yaml` files work unchanged.

## Automatic Grouping

ArcBox Desktop groups containers by Compose project with no configuration. Each project is a collapsible group whose header shows the project name and a `running / total` count.

Groups are ordered so live work stays at the top: projects with something running come first, then fully stopped ones.

## Project Operations

- **Start / Stop all** — the control on the group header applies to every container in the project, concurrently rather than one by one.
- **Delete All** — removes the whole project's containers, with a confirmation step.
- **Expand / Collapse** — click the project name.

Individual containers inside a group behave exactly like standalone ones: logs, terminal, info, and files. See [Using Containers](./containers).

## How Grouping Is Detected

ArcBox reads the standard Compose labels from container metadata:

```
com.docker.compose.project
com.docker.compose.service
```

Any tool that sets them groups correctly — `docker compose`, another Compose implementation, or labels you apply yourself.

## Compose Hostnames

Compose containers register two DNS names, so you can reach a service from your Mac without publishing a port:

```bash
# project "shop", service "api"
curl http://api.shop.arcbox.local:3000
curl http://shop-api-1.arcbox.local:3000
```

Inside the project's network, containers still reach each other by plain service name. See [Domains](./domains).

## Mixed Workflows

Run `docker compose up` in a terminal and manage the result in the GUI — state syncs through the Docker event stream in both directions. Stopping one service in the app shows up immediately in `docker compose ps`.
