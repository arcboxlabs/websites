## `abctl machine ssh`

```bash
abctl machine ssh dev
```

This opens an interactive login shell inside the machine. Despite the name, it is not the SSH protocol — the CLI opens a PTY session over the daemon's gRPC channel, puts your terminal in raw mode, and forwards window resizes. There are no keys to manage and no port to expose.

Pass a command to run it and exit instead of attaching:

```bash
abctl machine ssh dev uptime
```

For scripting, `abctl machine exec` is the non-interactive equivalent:

```bash
abctl machine exec dev -- cat /etc/os-release
```

## From the Desktop App

Select a machine and open its **Terminal** tab. It is the same session, in a window.

## Using a Real SSH Server

<Callout type="warn">
  Machines do not run an SSH server by default, and ArcBox does not provision keys or write entries into your `~/.ssh/config`. `ssh`, `scp`, and `rsync` against a machine only work once you set one up yourself.
</Callout>

If you need SSH — for an editor's remote-development mode, for example — install and configure it inside the machine:

```bash
abctl machine ssh dev
sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
mkdir -p ~/.ssh && printf '%s\n' 'ssh-ed25519 AAAA...' >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
```

The machine's hostname resolves from your Mac, so you can then connect normally:

```bash
ssh user@dev.arcbox.local
scp ./file.txt user@dev.arcbox.local:~/
```

## Moving Files Without SSH

For everyday file movement, prefer the paths that already exist:

- Your home directory is shared into every machine — see [File Sharing](./file-sharing).
- The **Files** tab in the Desktop app browses the guest filesystem and downloads from it.
