## What a Template Is

A template is a Dockerfile shipped inside the `abctl` binary, so a sandbox image for a known workload can be built without you writing or hosting anything. Templates go through the same build path as `--from-dockerfile` — they are an input to it, not a separate mechanism.

## Built-in Templates

```bash
abctl sandbox templates
```

| Template | Description |
|----------|-------------|
| `claude` | Claude Code on Node.js 22 with `git`, `ripgrep`, and `less`, running as a non-root user |

Use one directly:

```bash
abctl sandbox create --id t1 --from-template claude --memory 2048
```

`abctl claude` uses this template for you — see [Sandboxes](./sandbox#coding-agents).

## Customizing a Template

Print a template's Dockerfile, edit it, and build your version:

```bash
abctl sandbox templates --show claude > Dockerfile
# edit Dockerfile
abctl sandbox create --id mine --from-dockerfile ./Dockerfile --memory 2048
```

## Building From a Docker Image

Any image you already have works as a rootfs source:

```bash
abctl sandbox create --id build --from-image node:22 --cpus 2 --memory 2048
```

<Callout type="warn">
  Only the image's **filesystem** becomes the sandbox rootfs. `ENV`, `USER`, `WORKDIR`, and `ENTRYPOINT` are not carried over, so supply them when you exec — with `--user`, absolute paths, or an explicit `PATH`.
</Callout>

## Caching

Converted rootfs images are cached and keyed on the source layer content, so rebuilding an unchanged image reuses the conversion. Editing the Dockerfile changes the key and triggers a fresh build.
