## Image List

**Images** under **Docker** in the sidebar lists every image on the system with its repository, tag, size, and age. `⌘F` filters; the sort menu orders by name, size, or date.

## Pull an Image

`⌘N` opens the pull sheet. Enter a reference — `nginx`, `postgres:16`, `ghcr.io/org/app:latest` — and ArcBox pulls it with layer-by-layer progress. Layers you already have are skipped.

Or from the CLI:

```bash
docker pull nginx
docker pull --platform linux/amd64 nginx   # amd64 on Apple Silicon works too
```

## Run From an Image

Create a container from the selected image; the new-container sheet opens with it prefilled. See [Using Containers](./containers#creating-containers).

## Remove

Delete an image from its row. Images in use by a container cannot be removed until that container is gone.

Clean up dangling layers left behind by rebuilds:

```bash
docker image prune
```

## Private Registries

Docker Hub is the default registry, and public images pull without authentication. For anything private, log in with the Docker CLI:

```bash
docker login ghcr.io
docker login registry.example.com
```

ArcBox uses the same credential store as the Docker CLI — `docker-credential-osxkeychain` is bundled, so credentials land in the macOS Keychain by default. If `~/.docker/config.json` names a different credential helper, ArcBox honors it. Once you are logged in, private images work from both the CLI and the GUI.

## Building

`docker build` and `docker buildx` work unchanged; BuildKit is the default engine and `buildx` is bundled.

<Callout type="info">
  BuildKit's build cache is not shown in the Images view. Manage it with `docker builder prune`.
</Callout>
