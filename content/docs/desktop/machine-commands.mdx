## Managing Machines

```bash
abctl machine create dev --distro ubuntu   # create a machine
abctl machine list                         # list machines
abctl machine start dev
abctl machine stop dev
abctl machine remove dev

abctl machine status dev                   # current state
abctl machine inspect dev                  # full configuration
abctl machine info dev                     # guest system info
abctl machine ping dev                     # check the guest agent responds
```

Add `--format json` to any of them for machine-readable output.

## Getting a Shell

```bash
abctl machine ssh dev                # interactive shell
abctl machine ssh dev uptime         # run one command over the same path
abctl machine exec dev -- uname -a   # run one command via the daemon's exec RPC
```

`ssh` allocates a PTY and forwards terminal resizes, so full-screen programs work. `exec` is the non-interactive path — use it in scripts.

The Desktop app's **Terminal** tab on a machine gives you the same shell.

## Inside a Machine

Once you have a shell, it is an ordinary Linux system:

```bash
# Package management (Ubuntu)
sudo apt update && sudo apt install -y build-essential

# System services
sudo systemctl status ssh
sudo systemctl restart nginx
```

## Running Docker Inside a Machine

A machine can run its own Docker daemon, independent of the ArcBox container runtime:

```bash
sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo docker run hello-world
```

Useful for Docker-in-Docker workflows or containers with kernel requirements you do not want to apply to the System VM.

## Reaching Machine Services from Your Mac

Machines register a hostname, so every port is reachable without forwarding:

```bash
# Machine "dev" running a web server on port 3000
curl http://dev.arcbox.local:3000
```

See [Domains](./domains).
