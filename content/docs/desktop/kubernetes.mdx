## Overview

ArcBox runs a real Kubernetes cluster — [k3s](https://k3s.io), managed by the daemon inside the System VM. It is not a viewer bolted onto whatever cluster your kubeconfig happens to point at.

The Desktop app covers the resources developers touch most: **Pods** and **Services**.

## Starting the Cluster

<Tabs items={['Desktop', 'CLI']}>
  <Tab>
    Open **Pods** or **Services** under **Kubernetes** in the sidebar. If the cluster is off, the pane shows **Kubernetes Disabled** with a **Turn On** button.
  </Tab>
  <Tab>
    ```bash
    abctl k8s start
    abctl k8s status
    ```
  </Tab>
</Tabs>

## Connecting `kubectl`

```bash
abctl k8s enable
```

This installs `kubectl`, merges the ArcBox-managed kubeconfig into `~/.kube/config`, and switches your current context to the ArcBox cluster. `abctl k8s disable` restores the context you had before.

To handle the kubeconfig yourself instead:

```bash
abctl k8s kubeconfig > arcbox.yaml
KUBECONFIG=arcbox.yaml kubectl get nodes
```

<Callout type="info">
  **Settings → System → Switch Docker & Kubernetes context automatically** keeps the context pointed at ArcBox while the app runs.
</Callout>

## Pods

The pods list groups by namespace and shows each pod's status, container readiness, and age.

Select a pod to see its containers. Logs and terminal access work exactly as they do for Docker containers.

## Services

The services list shows type (ClusterIP, NodePort, LoadBalancer), ports, selectors, and the pods each service resolves to.

## Lifecycle

```bash
abctl k8s stop      # stop the cluster, keep its state
abctl k8s restart
abctl k8s delete    # discard cluster state entirely
```

`delete` removes the cluster's data. Workloads have to be reapplied afterwards.
