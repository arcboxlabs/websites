Open settings with `⌘,` or from the app menu. There are four panes: **General**, **Account**, **System**, and **Storage**.

## General

### Startup

| Setting | Default | What it does |
|---------|---------|--------------|
| **Start at login** | Off | Registers ArcBox as a macOS login item |
| **Show in menu bar** | Off | Adds a menu bar item with container controls and live metrics |
| **Keep running when app is quit** | Off | Leaves the daemon and your workloads running after you close the window. Requires **Show in menu bar** as well — closing the window then hides the app instead of terminating it |

<Callout type="warn">
  With the defaults, quitting ArcBox Desktop stops the daemon and everything it runs, and restores your previous Docker context. Choosing **Quit** from the menu bar item shuts the daemon down even when both settings above are enabled — use the window close button to keep it alive.
</Callout>

### Updates

Automatic update checks and automatic download-and-install, plus a **Stable** / **Beta** channel picker. New installs default to installing updates automatically. See [Updates](./updates).

### Privacy

<Callout type="warn">
  **Share anonymous usage data** is **on** by default. It sends feature-usage statistics — no account, no container data, no filesystem content. Turn it off here. See [Security](./security#telemetry).
</Callout>

### Terminal

- **Terminal theme** — System, Light, or Dark for the built-in terminal.
- **External terminal app** — which app opens when you choose to open a terminal in a new window. ArcBox lists the terminals it finds, and **Choose…** picks any app bundle.

### Troubleshooting

**Export Diagnostic Report…** collects logs and system state into a file you can attach to an issue.

## Account

Sign in to an ArcBox account to use ArcBox Platform features. Signing in opens your browser.

<Callout type="info">
  An account is optional. Everything local — containers, Kubernetes, machines, sandboxes — works signed out. Signing out does not touch your local containers or settings.
</Callout>

## System

### Environment

**Switch Docker & Kubernetes context automatically** (on by default) points the `docker` and `kubectl` contexts at ArcBox while it runs, and restores the previous ones when you turn it off.

### Compatibility

**Virtual machine backend** chooses the hypervisor for the System VM:

| Backend | amd64 translation |
|---------|-------------------|
| Virtualization.framework (default) | Rosetta |
| Hypervisor.framework | [FEX](https://github.com/FEX-Emu/FEX) |

<Callout type="error">
  Switching backends restarts the System VM and **stops all running containers**. Images and container data are preserved. [Sandboxes](./sandbox) require the Virtualization.framework backend.
</Callout>

The same switch is available as `abctl system backend hv|vz`.

**Pause containers while Mac is sleeping** (on by default) improves battery life. Turn it off only if you need background services to keep running with the lid closed.

## Storage

### Data

Your data lives under `~/.arcbox`. **Include data in Time Machine backups** is off by default — ArcBox adds a `tmutil` exclusion, since VM disk images churn constantly and back up poorly.

### Danger Zone

<Callout type="error">
  **Reset Docker Data** stops all containers and prunes every container, image, volume, and network. **Reset All Data** does the same and is the broader reset. Neither can be undone.
</Callout>

Machine and sandbox data is not covered by these buttons — remove those individually, or uninstall. See [Installation](./install#uninstall).

## Not Yet Available

Storage location, "Hide ArcBox volume from Finder & Desktop", "Reset Kubernetes Cluster", and VM CPU/memory limits appear in the UI but are inactive pending daemon support. See [Known Issues](./known-issues).
