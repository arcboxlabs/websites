## Comparison

| | ArcBox | Docker Desktop |
|--|--------|----------------|
| **Pricing** | Free — personal, and commercial during the public beta | Free for personal, paid for larger businesses |
| **Open source** | Yes — runtime and desktop app, MIT OR Apache-2.0 | Proprietary |
| **Account required** | No | Yes |
| **Platform** | macOS on Apple Silicon | macOS, Windows, Linux |
| **Docker compatibility** | Drop-in Engine API, Compose v2, BuildKit | Reference implementation |
| **Kubernetes** | k3s cluster managed by the daemon | Built-in cluster |
| **Linux machines** | Built-in, full VMs | Not available |
| **Sandboxes** | Built-in microVMs with snapshots | Not available |
| **Zero-config hostnames** | `name.arcbox.local` | Not available |
| **Docker Extensions** | Not supported | Supported |
| **Windows containers** | Not supported | Supported |
| **Vulnerability scanning** | Not built in | Docker Scout |

## What's Better in ArcBox

- **Open source end to end.** The VMM, the device model, the networking datapath, and the SwiftUI app are all inspectable and forkable. There is no closed core.
- **No account, ever.** Nothing to sign into, no license key.
- **Built-in Linux machines and sandboxes.** Full VMs when a container is not enough; microVMs with their own kernel when a container is not isolated enough.
- **Zero-config hostnames.** Reach any container or machine at `name.arcbox.local` without publishing a port.
- **A file browser that shows the merged filesystem.** Container layers unioned into one tree, backed by a real Finder-visible volume at `~/ArcBox`.

## What Docker Desktop Has That ArcBox Doesn't

- **Docker Extensions** marketplace
- **Windows containers**
- **Intel Mac support** — ArcBox is Apple Silicon only for now
- **Windows and Linux desktop clients**
- **Docker Scout** vulnerability scanning
- **Maturity** — Docker Desktop is the reference implementation; ArcBox is in public beta

## Migrate from Docker Desktop

<Steps>
  <Step>
    ### Install ArcBox

    [Install ArcBox Desktop](./install). Leave Docker Desktop installed for now.
  </Step>
  <Step>
    ### Quit Docker Desktop

    Quit it from the menu bar so it releases `/var/run/docker.sock`.
  </Step>
  <Step>
    ### Import Your Workloads

    ```bash
    abctl migrate from docker-desktop
    ```

    This reads Docker Desktop's data directory and imports your containers, images, and volumes. Pass `-y` to skip the confirmation prompt, or `--source-socket` if its socket is not at the usual path.
  </Step>
  <Step>
    ### Point the Docker CLI at ArcBox

    ```bash
    abctl docker enable
    docker info
    ```

    `docker info` should now report the ArcBox runtime.
  </Step>
  <Step>
    ### Start Your Projects

    ```bash
    docker compose up -d
    ```

    Compose files work without modification.
  </Step>
  <Step>
    ### Uninstall Docker Desktop (Optional)

    Once you have verified everything, remove Docker Desktop from Applications.
  </Step>
</Steps>

## Differences to Expect

<Callout type="info">
  Docker Extensions and Windows containers have no ArcBox equivalent. If you depend on a specific Extension, check that ArcBox covers what you use it for before you migrate.
</Callout>

<Callout type="warn">
  Host ports below 1024 cannot be published — port forwarding runs unprivileged. Use a high host port, or reach the container at `name.arcbox.local` on its own port. See [Networking](./networking#port-mapping).
</Callout>
