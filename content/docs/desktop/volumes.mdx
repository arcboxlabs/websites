## Volume List

**Volumes** under **Docker** in the sidebar lists every Docker volume with its driver and creation time. `⌘F` filters; the sort menu reorders.

## Create a Volume

`⌘N` opens the new-volume sheet. Name it; the `local` driver is used unless you say otherwise.

Or from the CLI:

```bash
docker volume create my-data
```

## Remove

Delete a volume from its row. Volumes in use by a container cannot be removed.

To clean up everything unused:

```bash
docker volume prune
```

<Callout type="error">
  Removing a volume deletes its data. There is no undo.
</Callout>

## Bind Mounts vs Volumes

**Bind mounts** map a directory on your Mac into a container. Because ArcBox shares `/Users` into the guest at the same path, the path you write is the path the container gets — no translation:

```bash
docker run -v /Users/you/project:/app my-image
```

Use them for source code and config you want to edit on macOS.

**Volumes** are managed by the runtime and live on the guest's own filesystem, which means no cross-boundary metadata traffic. Use them for databases and other write-heavy state.

<Callout type="info">
  As of 1.31, metadata-heavy work over bind mounts — `node_modules` scans, file watchers, stat storms — is 20–60% faster than in earlier releases. Volumes still win for databases.
</Callout>

## Reclaiming Space

Volume data lives on the shared Docker data image. To see and reclaim what it occupies on your Mac:

```bash
abctl disk usage
abctl disk compact
```
