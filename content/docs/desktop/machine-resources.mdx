## Defaults

| Resource | Default | Flag |
|----------|---------|------|
| CPU | Host core count | `--cpus` |
| Memory | 4096 MB | `--memory` (MB) |
| Disk | 50 GB | `--disk` (GB) |

```bash
abctl machine create dev --cpus 4 --memory 8192 --disk 100
```

Omitting `--cpus` lets the daemon pick the host core count.

## Changing Resources

Resources are set when the machine is created. Changing CPU or memory afterwards means recreating the machine — the disk is separate from the machine record, so plan the disk size up front.

## Sharing With the Host

Machines, containers, and your Mac share the same physical CPU and memory. Allocation is an upper bound, not a reservation: a machine given 8 GB does not take 8 GB from the host until the guest actually uses it.

<Callout type="warn">
  Memory the guest has touched is not returned to macOS while the machine runs. Stopping the machine is what frees it. Size machines for what they need rather than for headroom.
</Callout>

## Monitoring

The machine's **Info** tab shows its configuration, and **Activity** under **System** shows live CPU, memory, and network for the System VM and running containers.

From the terminal:

```bash
abctl top          # live view
abctl top --once   # one sample and exit
```

## Disk Space

Container and image data lives on the shared Docker data image, not in a machine. Check and reclaim it with:

```bash
abctl disk usage
abctl disk compact
```
