## Default Network

Every container joins the default bridge network. Containers on the same network reach each other by container name through Docker's own DNS. No configuration is needed for most development workflows.

ArcBox's networking datapath runs entirely in userspace on the host — DHCP, DNS forwarding, TCP, and socket proxying — with no `pf` NAT rules and no `utun` device.

## Port Mapping

Publish a container port with `-p`:

```bash
docker run -d -p 8080:80 nginx
```

The daemon binds a host listener per rule and forwards traffic into the guest, so the service is reachable at `localhost:8080`.

<Callout type="info">
  Publishing is unprivileged, which means host ports below 1024 cannot be bound. Use a high port and reach the container directly at `<name>.arcbox.local` when you need the real port number.
</Callout>

Published ports appear in the container list and on the **Info** tab.

## Reaching the Host from a Container

Your Mac is reachable from inside a container at:

```
host.docker.internal
gateway.docker.internal
```

Useful for connecting to a database, API, or dev server running natively on macOS.

## Container-to-Container

Containers on the same user-defined network reach each other by name:

```bash
docker network create my-net
docker run -d --name db --network my-net postgres
docker run -d --name app --network my-net my-app
# "app" connects to "db" using the hostname "db"
```

## Reaching Containers from Your Mac

Containers are also reachable at `<name>.arcbox.local`, on whatever port the service actually listens on — no publishing required. See [Domains](./domains).

## Managing Networks

**Networks** under **Docker** in the sidebar lists every Docker network with its driver, subnet, and attached containers, and lets you create and delete them. The built-in `bridge`, `host`, and `none` networks cannot be removed.

## amd64 Images

`linux/amd64` images run alongside native arm64 with no configuration. Translation happens inside the guest — Rosetta on the Virtualization.framework backend, [FEX](https://github.com/FEX-Emu/FEX) on the Hypervisor.framework backend.

```bash
docker run --platform linux/amd64 alpine uname -m
# x86_64
```

## VPN Compatibility

ArcBox reserves `172.16.0.0/12` for container networks and adapts when a VPN client claims that route. See [VPN Compatibility](./vpn-compatibility) for the routing behavior, Surge configuration, and verification steps.
