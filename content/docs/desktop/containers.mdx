## Container List

**Containers** under **Docker** in the sidebar lists everything on the system. Each row shows the name, image, state, and published ports — click a port to open it in your browser.

The list is organized so running work stays at the top:

- **Compose projects with something running**, then their stopped counterparts
- **Standalone running containers**, then stopped ones

Compose projects appear as collapsible groups with a `running / total` count in the header. See [Compose Projects](./compose).

## Operations

**Per container** — the row has start/stop and delete controls. Right-click for **Start** / **Stop**, **Copy Name**, **Copy ID**, and **Delete**. Deleting asks for confirmation.

**Per Compose project** — the group header starts or stops every container in the project at once, and offers **Delete All**. These run concurrently rather than one after another.

## Creating Containers

`⌘N` in the container list opens the new-container sheet, where you can set:

- Name and image
- Platform (`linux/arm64` or `linux/amd64` — see [Networking](./networking#amd64-images))
- Port mappings
- Environment variables
- Volume mounts
- Network
- Restart policy

You can also create one from the **Images** view, or from `docker run` — the GUI picks it up either way.

## Filtering and Sorting

`⌘F` focuses the search field to filter by name or image. Sort by **Name**, **Date Created**, or **Status**, ascending or descending, from the sort menu in the toolbar.

## Detail Tabs

Select a container to open its detail view.

<Tabs items={['Info', 'Logs', 'Terminal', 'Files']}>
  <Tab>
    The container's configuration in readable sections rather than raw JSON — the same data as `docker inspect`:

    - **Environment variables** set at build or run time
    - **Port mappings** between host and container
    - **Mounts** — volumes and bind mounts with source and destination
    - **Network** — attached networks, addresses, and aliases
    - **Labels**, including Compose metadata
    - **Health check** and **restart policy**
  </Tab>
  <Tab>
    Logs stream in real time and the view follows output until you scroll up.

    **Search** filters and highlights matching lines. **Timestamps** can be toggled on or off. Selected lines copy with `⌘C`.

    <Callout type="info">
      The viewer handles high-throughput output without blocking the UI. For containers producing extreme log volume, `docker logs --tail` from the CLI limits the initial load.
    </Callout>
  </Tab>
  <Tab>
    An interactive shell inside a running container — the equivalent of `docker exec -it <container> /bin/sh`.

    Colors, cursor movement, and full-screen programs like `top` or `vim` work as expected, and the terminal resizes with the window. `⌘C` and `⌘V` copy and paste.

    Prefer your own terminal app? Set **Settings → General → External terminal app**.

    <Callout type="warn">
      This needs a running container with a shell binary. Stopped containers and `scratch`-based images have nothing to attach to.
    </Callout>
  </Tab>
  <Tab>
    The container's filesystem as the process sees it: the writable layer merged over the image layers below it, with whiteouts honored.

    Files open in their default macOS app, and **Reveal in Finder** jumps to the real path under `~/ArcBox`. The view is read-only. See [File Access](./file-access).
  </Tab>
</Tabs>

## Resource Usage

Live CPU, memory, and network for every running container are in **Activity** under **System** in the sidebar, alongside the System VM's own metrics. `abctl top` shows the same data in a terminal.

## Real-time Sync

ArcBox follows the Docker event stream. Containers created or changed by the CLI, Compose, or any other tool show up in the GUI within a fraction of a second, and actions taken in the GUI show up immediately in `docker ps`.
