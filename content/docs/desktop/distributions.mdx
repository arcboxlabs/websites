## Available Images

Machine images are mirrored from [images.linuxcontainers.org](https://images.linuxcontainers.org) and published as versioned, immutable streams named `{distro}-{release}-{arch}`:

| Distribution | Releases | Status |
|-------------|----------|--------|
| **Ubuntu** | `noble`, `resolute` | Tested — default |
| **Alpine** | `3.23`, `3.24` | Tested |
| **Debian** | `trixie`, `forky` | Mirrored |
| **Fedora** | `43`, `44` | Mirrored |
| **Arch Linux** | `current` | Mirrored |

Both `arm64` and `amd64` are published. Ubuntu is the default when you do not pass `--distro`.

<Callout type="info">
  Ubuntu and Alpine are the paths that are exercised regularly. The other distributions are mirrored and selectable, but you may hit rough edges — please [report them](https://github.com/arcboxlabs/arcbox/issues).
</Callout>

## Choosing a Distribution

<Tabs items={['Desktop', 'CLI']}>
  <Tab>
    Pick the distribution in the machine creation sheet.
  </Tab>
  <Tab>
    ```bash
    abctl machine create dev --distro ubuntu
    abctl machine create dev --distro ubuntu --distro-version noble
    abctl machine create web --distro alpine --distro-version 3.24
    ```

    `--distro-version` accepts the codename (`noble`) or the user-facing release (`24.04`). Omit it when the distribution has exactly one published release for your architecture.
  </Tab>
</Tabs>

## Pinned Versions

Each stream keeps several dated builds. Referring to a stream follows its latest build; pinning `stream@version` reproduces an exact one. Older builds stay retrievable on the CDN even after they drop out of the index, so a pinned reference keeps working.

## What's Included

Images are the upstream distribution's default variant — a base system with its package manager configured, and nothing else. Compilers, runtimes, and language toolchains are not preinstalled.

<Callout type="warn">
  No SSH server is installed or enabled. Use `abctl machine ssh` for a shell, or install `openssh-server` yourself — see [Shell Access](./ssh).
</Callout>

## Custom Kernels

For testing, a machine can boot a kernel you supply:

```bash
abctl machine create test --kernel /path/to/vmlinux --cmdline "console=hvc0 ..."
```

Both flags are for development and debugging; the bundled kernel is what normal machines use.
